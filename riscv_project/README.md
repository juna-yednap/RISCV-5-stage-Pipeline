# riscv_project

Testbench setup for `riscv_cpu` / `riscv_cpu_wrapper`.

## Directory structure

```
riscv_project/
├── rtl/                     <- all your design files live here
│   ├── riscv_cpu.v          (provided)
│   ├── riscv_cpu_wrapper.v  (provided)
│   ├── controller.v         <- add your existing file here
│   ├── datapath.v           <- add your existing file here
│   └── ...                  <- any other submodules (alu.v, regfile.v,
│                                hazard_unit.v, etc.) go here too
├── tb/
│   ├── instr_mem.v          instruction memory model (sim-only)
│   ├── data_mem.v           data memory model (sim-only)
│   └── riscv_cpu_tb.v       the testbench itself
├── programs/
│   ├── default.txt            used when no program is specified
│   ├── template.txt            blank starting point for your own program
│   ├── sum_1_to_5.txt         GOAL: repeated addition via a loop -> x2 = 15
│   ├── simple_branch.txt      GOAL: if/else branch -> x3 = 2
│   ├── mem_store_load.txt     GOAL: store then load -> x2 = 42
│   └── loop_countdown.txt     GOAL: backward branch loop -> x2 = 5, x3 = 1
├── scripts/
│   ├── run.sh                 compile + run one program
│   └── run_all.sh             compile once, run every program in programs/
├── build/                    compiled sim binary (generated)
├── waves/                    .vcd waveform output (generated)
└── logs/                     per-program console output (generated by run_all.sh)
```

`rtl/` should end up containing everything needed to elaborate `riscv_cpu_wrapper`:
`riscv_cpu.v`, `riscv_cpu_wrapper.v`, `controller.v`, `datapath.v`, and
whatever `datapath.v` itself instantiates. Only the two files you uploaded
are here right now — drop the rest of your existing RTL into `rtl/` and
everything below just works, since both `run.sh` and the `Makefile` compile
`rtl/*.v` as a glob.

## How the instruction-file flow works

`tb/instr_mem.v` loads a program at simulation start via Verilog's
`$readmemh`, reading whichever file is passed in with `+MEMFILE=<path>`
at run time (no recompiling needed to switch programs). Each line of the
program file is one 32-bit instruction written as 8 hex digits, e.g.:

```
00500093   // addi x1, x0, 5
00a00113   // addi x2, x0, 10
```

`//` comments and blank lines are fine. `programs/template.txt` is a
blank starting point. Each other program targets one specific thing and
says so up top, with an expected final register value to check against:

- **`sum_1_to_5.txt`** — repeated addition via a loop (`sum = 1+2+3+4+5`).
  Expect `x2 = 15`.
- **`loop_countdown.txt`** — a backward branch loop (`bne` jumping back to
  a lower PC), counting `x1` down from 5 while accumulating `x2`. Expect
  `x2 = 5, x3 = 1`. Best one for checking your pipeline flushes correctly
  on a taken backward branch.
- **`simple_branch.txt`** — a plain if/else (`beq` skipping the "then"
  path). `x1 != x2` here, so the else path should run. Expect `x3 = 2`.
- **`mem_store_load.txt`** — write a value to memory, then read it back.
  Expect `x2 = 42`, matching what was stored.

Note this expects raw machine code, not assembly mnemonics — hand-encode
it, or use an RV32I assembler if you have one
(`riscv64-unknown-elf-as` + `objdump -d`) to get hex from real assembly.

## Running

```bash
chmod +x scripts/run.sh        # once

./scripts/run.sh                                   # default.txt, 100 cycles
./scripts/run.sh programs/sample1.txt               # specific program
./scripts/run.sh programs/sample1.txt 60            # for 60 cycles
./scripts/run.sh programs/sample1.txt 60 -f          # force clean recompile
```

To run every program in `programs/` back to back (compiles once, then loops
through each `.txt` file), saving each run's console output to `logs/<name>.log`
and each waveform to `waves/<name>.vcd`:

```bash
chmod +x scripts/run_all.sh     # once
./scripts/run_all.sh            # 100 cycles per program
./scripts/run_all.sh 200        # 200 cycles per program
```

Or run the raw iverilog/vvp commands directly:

```bash
iverilog -g2012 -o build/sim.out rtl/*.v tb/instr_mem.v tb/data_mem.v tb/riscv_cpu_tb.v
vvp build/sim.out +MEMFILE=programs/sample1.txt +CYCLES=60
```

Each run prints a per-cycle trace (`pc`, `result`, memory writes) to the
console and writes `waves/riscv_cpu_tb.vcd`, viewable with:

```bash
gtkwave waves/riscv_cpu_tb.vcd
```

## Notes

- `instr_mem` / `data_mem` are 256-word (1KB) sim-only memories; bump
  `DEPTH` in `tb/instr_mem.v` / `tb/data_mem.v` if a program needs more.
- `riscv_cpu_tb.v` holds `reset` high for the first 12ns (a bit over one
  clock edge) then releases it, matching the classic Harris & Harris
  RISC-V testbench reset convention this design's port names come from.
- This has been sanity-checked to compile and run end-to-end with
  Icarus Verilog (stub `controller`/`datapath` used only for that check,
  not included here) — swap in your real files and it should compile the
  same way.
